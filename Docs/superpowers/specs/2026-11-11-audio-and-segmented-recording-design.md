## 1. 意图与原因

SnapGlass 现在只能录屏，且音频只有"系统声音"一条路，麦克风完全没有代码。用户需要的是**会议级的快速录制**：一键开始、录多久都不怕、录完立刻能听、需要时能把两个小时的会议交给剪辑或转写。

这带来三件今天不存在的能力：

1. **纯音频录制**，来源为系统声音、麦克风或两者。
2. **长时录制不脆**：正常产物每段不超过 59 分钟，内部另有崩溃恢复暂存；已提交的检查点可恢复，目标恢复点窗口不超过 5 分钟。
3. **录完能处理**：在应用内选段、裁剪、调增益、导出（单次上限 1:59:30）。

以及一件必须修掉的体验缺陷：今天**录制期间截图被直接拦截**（`RecordingCaptureAvailability.canBeginCapture(isRecordingBusy:)` 返回 false），录屏时想截一张图会被静默拒绝——这是"录制与截图互斥"的旧设计，必须废除。

### 1.1 本轮用户约束与证据边界

- **用户已确认**：正常录制自动分段，不生成超长总文件；崩溃兜底暂存不能省略。2 小时 = 59 分钟 + 59 分钟 + 2 分钟三段，不是两个文件。
- **用户已纠正**：音频单轨自动混合当前启用的来源，来源切换/组合不中断；音频多轨分文件、带时间码；视频按来源分轨，音轨直接封在视频文件内。
- **视频不重编码**：录制时首次编码不属于重编码；后续封装、拼接、裁剪均不得再次编码视频。音频混音、增益、补静音可能需要音频编码，必须与视频直通分开标识。
- **功能不缩水**：动态切音源、截图共存、恢复、多轨、导出与可达性均为交付要求，不以禁用功能换取低开销。
- **本轮已观察的代码**：`ScreenRecordingEngine.swift` 当前只有一个 MP4 writer，首帧视频决定起点，音频遇背压直接跳过；`RecordingConfiguration.swift` 未设置 GOP 上限；`RecordingSessionController.swift` 收到锁屏通知会停止录制。新设计不是这些能力已存在的声明。
- **项目风格判断**：有分层、纯决策类型、真实 writer 测试与原子发布机制，按既有模式扩展；不另建媒体框架。
- **未验证**：设备漂移、AAC trim 元数据、MP4 多音轨播放、分片首帧及长时性能。文中的预算/阈值是设计目标，不是实测结果。

## 2. 目标 / 非目标 / 反目标

### 目标

| # | 目标 | 验收 |
|---|---|---|
| G1 | 音频三模式：系统声音 / 麦克风 / 两者 | 三种模式均产出可播放文件；双源模式两路都可分辨 |
| G2 | 音频输出可配置：单轨混音（默认）/ 多轨分轨 | 单轨自动混合；多轨 = 同目录多个音频文件 + 整数样本时间码 |
| G3 | 录屏可选麦克风，按来源内嵌分轨 | 四模式可选（含静音）；系统/麦克风为 MP4 内独立音轨，不以混音替代 |
| G4 | 正常录制每段 ≤ 59 分钟，时间轴连续 | PCM 边界样本守恒；AAC 有效样本 trim 正确；视频接缝无重复/丢失已接收帧 |
| G5 | 抗崩溃、抗卡顿 | 进程崩溃恢复点窗口目标 ≤ 300 秒；采集回调不等待写盘；超预算有明确故障路径 |
| G6 | 应用内拼接与导出 | 选段、裁剪、增益、单轨/分轨输出，上限 1:59:30 |
| G7 | 录制期间可正常截图 | 截图不被拦截；截图架可用；录制画面不含录制 UI |
| G8 | 菜单栏优先，热键可选 | 热键默认未设置；设置页有空态引导 |
| G9 | 录制中切音源/设备不断会话 | session ID、段计时及视频流不重启；缺失来源原位补静音 |
| G10 | 视频码流直通 | 封装/拼接/裁剪不调用视频编码器，压缩样本载荷可核对 |

### 非目标

- 暂停/恢复录制（v1 明确不做；HUD 也不留假按钮）
- 云端转写、字幕、AI 摘要
- 视频剪辑、转场、多轨视频时间线
- 推流、直播、系统级虚拟声卡
- 引入 FFmpeg 或任何外部二进制
- 修改最低系统版本（保持 macOS 13）
- 修改 `Package.swift` 的既有协议定义或新增 SPM 依赖
- 帧精确的视频重编码裁剪（本轮明确移除该选项）

### 反目标（技术上成立也算失败）

- 录了 3 小时，导出时崩了或丢了一段。
- 需要用户自己去 Finder 里把 12 个分片拼起来才能听（chunk 必须永远不可见）。
- 录音时想截一张图，发现被应用拦住。
- 双源录音听起来是"两个人在两个房间里"（回声/漂移）。
- 分段文件各自能播，接缝处"咔"一声。
- 多轨模式下用户拿到 3 个看不出关系的文件。
- 换一次麦克风就重启会话，或者系统声音重新启用时视频断开。
- 为了兼容播放而偷偷把视频来源合成唯一音轨，丢掉分轨能力。

## 3. 约束

### 平台

1. **本项目系统声音统一选择 ScreenCaptureKit**，保持 macOS 13 基线，不为较新系统另写 Core Audio process tap 路径。纯录音先按低帧率 2×2 配置做兼容基线，audio-only 是否可用交 P0 验证，不断言所有系统都必须收视频。含系统声音的模式需要屏幕录制授权，引导文案必须说清。
2. **本项目麦克风统一选择 AVAudioEngine**，避免依赖较新系统的 SCK 麦克风接口，不维护两套麦克风代码；这不是声称其他 CoreAudio API 无法采集麦克风。
3. **不能假定未完成 writer 的文件可恢复**。Apple 的 `movieFragmentInterval` 确实支持部分容器的片段写入，因此原稿“AVAssetWriter 不产出 fragmented MP4”的绝对断言撤销；具体 MP4/系统/异常组合仍须实测。本轮用已关闭小分片作为恢复基线，不依赖活动文件一定可播放。
4. **AAC 是带 priming/padding 的有状态编码**。延迟依编码器、容器与播放器的 trim 处理而异，不能把历史常见的 2112 样本当作每次接缝固定误差。独立 AAC 分片的任意直通拼接不作为无缝基线；内部音频采用 PCM，段内每个输出轨仅有一次连续 AAC 编码（见 5.4）。
5. **产品约定**：纯音频多轨用目录 + 多文件；视频用 MP4 内多音轨。这不是声称 `.m4a` 容器规范绝对不能有多轨。
6. 未沙盒、ad-hoc 签名、`ENABLE_HARDENED_RUNTIME=NO`。麦克风**不需要 entitlement**，但需要 `NSMicrophoneUsageDescription`（缺失会导致进程被系统直接终止，不是弹窗）。ad-hoc 签名下 TCC 授权在更新后可能失效。

### 项目

- Swift 6、`-enable-upcomingFeature StrictConcurrency`、macOS 13+。
- 核心逻辑放 `CaptureCore`，无 AppKit；UI 与窗口行为留 App target。
- 所有 `public` API 有 DocC；界面文案四语言齐全；不手改 `.xcodeproj`。
- 现有录屏行为（H.264/HEVC、1080p 上限、8 Mbps、原子发布、失败保留 partial）不得回退。

## 4. 方案与取舍

### 4.1 延续已选方案，不重启架构讨论

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 统一时间轴 + 最小必要 PCM 暂存 | 单轨只写 mixed；多轨只写 source；视频图像独立编码后直通封装 | 恢复路径统一、没有冗余第三条轨、动态路由不改视频 | 需实现时钟映射、恢复账本与有界后台封装 |
| B 每个恢复分片独立 AAC | 内部小文件直接作为最终编码材料 | 暂存小、可减少 PCM IO | 任意拼接不能先验保证 priming/接缝正确；本轮不选 |
| C 依赖活动 fragmented 文件恢复 | 较长 writer 内持续写 movie fragments | 可能减少重封装与恢复损失 | API 存在不等于具体 MP4 崩溃路径已验证；作为后续 P0 对照，不替代可靠基线 |

**决定：保留 A 的采集泵与 PCM 恢复路线，修正其落盘策略**。不同时写 mixed + system + mic 三份；不承诺停止瞬间完成封装。B/C 只有在实测达到相同体验和恢复契约后才可另行替换，不用它们拖延当前完整目标。

### 4.2 多轨的定义

- **纯音频单轨**：当前启用来源自动混成一条，录制中变更路由仍写同一条 mixed 轨。
- **纯音频多轨**：同目录多个独立文件，按 source role 对齐，不额外保存混音副本。
- **视频**：一个 MP4 内保留 `system`、`microphone` 独立音轨，不另存外置音频副本、不默认附加 mixed 轨。只有一路来源时实际只有一路音频；静音录屏没有音频轨。“永远多轨”指按来源隔离，绝不以混音取代来源轨。
- 麦克风换设备仍属于 `microphone`，不是无限新增设备轨。输出形态在开始前选定，**音源路由可在录制中改变**。

### 4.3 分段策略

| 层级 | 单元 | 可见性 | 用途 |
|---|---|---|---|
| chunk/checkpoint | 最长 5 分钟，安全暂存始终启用 | 隐藏 | 崩溃恢复单元；5 分钟是恢复点窗口，不是用户分段时长 |
| segment | **最长 59 分钟** | 用户可见 | 正常产物；尾段可更短，视频按真实帧边界切分 |

59 而非 60，是为了让"两段拼满"= 1:58:00 稳落在 1:59:30 的导出上限之内，并留出 1:30 的裁剪余量。

### 4.4 会话结束时磁盘上有什么

- **不做自动总合并**，包括隐藏的超长总媒体文件。2 小时的录音正常得到 **3 段：59 + 59 + 2 分钟**；用户主动拼接导出另受 1:59:30 上限约束。
- 每到段边界，**立即轮转并排队封装**，录制继续；封装校验完成后才发布可见段，不把“到边界”说成“最终文件已保存”。安全检查点此前已独立落盘。
- 停止时封装最后一个不满 59 分钟的尾段。
- 纯音频正常产物数量 = `ceil(有效时长 / 3540s)`（零长度会话无产物）；视频用实际帧边界，可能略提前轮转。音频多轨是 N 组文件，视频是 N 个多音轨 MP4。
- HUD 分别显示“正在录第 N 段”和“已保存 M 段”，可有“整理中”，绝不把已关闭但未发布的段计为已保存。

## 5. 最终设计

### 5.1 术语

- **Session**：一次录制，从开始到停止；录制类型/输出形态固定，音源路由可变。
- **Chunk**：内部恢复分片，通常约 5 分钟，关闭并提交后才是检查点；不进入普通产物列表。
- **Segment**：用户可见的一段，最长 59 分钟；尾段或视频帧对齐后可更短。
- **Track**：一条逻辑音频来源（`mixed` / `system` / `microphone`）。
- **Seal**：把若干 chunk 合成一个可见 segment 的过程。
- **Epoch**：与采集时间戳建立映射的单调 host-time 原点；样本索引是它在 48 kHz 网格上的表示，不使用可跳变的墙钟。
- **RouteEvent**：在整数样本位置提交的来源开关/设备变更；不是新会话或新段。

### 5.2 音频泵（统一 host-time 映射，不让定时器充当声卡）

```
系统声音  SCStream(2×2, capturesAudio) ──► PCM ─┐
麦克风    AVAudioEngine tap → 格式归一化 ─────────┤→ 带采集时间戳的有界缓冲 → 对齐泵
                                                  │
                          48 kHz：每 10ms = 480 帧
                          按 host-time 水位消费，渐进重采样校正漂移
                          单轨才混音；分轨仅对齐；电平独立节流
                          PTS = 样本索引 / 48 000，索引映射到同一 epoch
                                                  │
                                     ┌────────────┴─────────────┐
                                     ▼                          ▼
                          音频单轨：仅 mixed PCM      音频多轨/视频：仅 source PCM
```

| 类型 | 职责 | 约束 |
|---|---|---|
| `AudioSourceRingBuffer` | 每路上限 2 s，携带 host-time/帧数 | 预分配；正常漂移不靠周期性丢样本解决；溢出明确记损失区间 |
| `AudioMixPolicy` | 求和、固定增益、限幅、静音判定 | 纯音频单轨才运行；常规块 480 帧，边界块可拆分 |
| `AudioSampleClock` | host-time ⇄ 整数样本 ⇄ `CMTime` | 不用浮点秒累计；保留设备时钟映射与残差 |
| `AudioMixPump` | 定时唤醒 + 按时间戳排齐/渐进重采样 | 定时器不决定媒体速度；不做文件 IO/编码/UI，不无限追帧 |
| `SystemAudioSource` | 纯录音用低帧率 2×2 SCK；录屏复用现有 SCK 音频输出 | 不为录屏再起第二个系统音频 stream；排除自身声音 |
| `MicrophoneSource` | 一个 tap；工作队列格式转换到固定会话格式 | 采集回调只拷贝和记录时标；设备事件驱动重配 |
| `AudioSampleBufferFactory` | `AVAudioPCMBuffer` ⇄ `CMSampleBuffer` | 复用缓冲池，避免逐帧分配 |
| `AudioRouteController` | 预备新来源、权限检查、原子提交 RouteEvent | 不重启视频 writer，不把设备时钟归零 |

**连续性与漂移分开证明**：所有输出共享整数样本网格，段之间连续；但计数连续不等于源信号没有丢失。系统 PCM 的 PTS 与麦克风 `AVAudioTime.hostTime` 要映射到同一 epoch，通过长期时间戳残差/缓冲水位估算速率差，做有界、缓变的重采样。不能把每隔一段时间“丢 500 ms 或塞静音”称作无漂移；P0 注入 ±100/±300 ppm 进行长时验证。

**有界背压而非无限保证**：来源缓冲与 PCM 写队列各有固定上限（初始预算均为 2 s，P0 校准）。短暂停顿由缓冲吸收；连续写盘落后时先暂停波形生成/导出，再提高检查点任务优先级。仍超预算则记录 `droppedRanges`、发出可行动告警并安全停止，不能悄悄丢声音还报告完整成功。视频可丢未接受的帧，音频文件时间轴不得前移。采集回调无锁等待、无逐块 Task 派发。

**麦克风信号**：v1 只有一个 tap，**全链路用原始麦克风信号**（不启用 voice processing）。单轨混音与多轨模式使用同一种麦克风信号，不做双链。voice processing 可另行调研，但不是本轮必跑 P0；后续确认有效且副作用可控时，才评估同一个 tap 上的设置项。

**A/V 同步**：录屏首个有效视频样本建立 epoch，短时预缓冲音频按采集时标裁去起点前数据/填补起点后空缺；纯录音从首个已准备好的来源建立 epoch。已开录时所有源暂时无声也不重置时钟。先核实时间戳包含的延迟语义，再用 CoreAudio 设备/流延迟校准残差，禁止把 latency、safety offset 无条件重复相加。有线/内置目标偏差 < 50 ms，蓝牙单列测试结果，不虚报相同延迟。

### 5.3 输出形态与落盘

| 录制类型 | 输出形态 | 产物 |
|---|---|---|
| 音频 | 单轨混音（默认） | 每段一个 `SnapGlass_2026-11-11_15-30-00-00.m4a`，后续 `…-01.m4a`、`…-02.m4a` |
| 音频 | 多轨 | 每段一个目录 `SnapGlass_2026-11-11_15-30-00-00/`：`system.m4a`、`mic.m4a`、`manifest.json`（**不混音**） |
| 视频 | 固定来源分轨（不提供混音/分轨二选一） | 每段一个 `.mp4`，1 条视频轨 + 本段曾启用的系统/麦克风独立音轨；不额外生成音频文件 |

多轨的对齐规则：

- 同一段内所有轨的 PTS 都以该段段首为 0。
- `manifest` 记录 `sampleRate`、`startSample`、`sampleCount`、实际视频边界 `CMTime {value,timescale}`，浮点秒只用于显示；不靠文件名或创建时间推导对齐。
- 纯音频段通常从 `N × 169920000` 样本开始；视频使用实际帧对齐边界，不硬套 `N × 3540s`。
- 音频文件嵌入 session/segment/role、起点及有效样本数的可读取元数据；MP4 内嵌同类会话描述及轨道 ID→role 映射。以 P0 验证过的键/schema 为准，不能只写在应用索引里。
- 多轨音频目录提供逐轨同长文件与 `manifest.json`。DAW 可从各文件 0 同起点导入同一段，跨段按整数样本偏移排列；不声称所有 DAW 都会自动读取自定义 JSON/M4A 元数据。
- 本段曾启用某来源，则为它生成覆盖整段的轨：未启用、拔出或重配区间补静音。本段从未启用的来源不创建无用轨；历史已发布段不可因后来开麦而重写。
- 每个角色的采样率/输出声道数在会话中固定；更换输入设备通过 converter 映射，不让驱动格式变化改变已发布文件的格式。后启用来源可从账本生成段首静音，再接上实际 PCM，无需回写先前 chunk。

**播放语义**：应用内预览默认同步混合所有来源轨，按需独听；预览混音不落盘。第三方播放器可能只选播其中一条，不能保证都自动混音。轨道必须命名清楚，不误标成可互换的语言版本；P0 验证 QuickTime、系统预览与剪辑导入，必要时明确提示选轨，并提供既有的“仅音频混音导出”，不靠删除独立来源来换兼容。

**命名**：沿用 `SnapGlass_yyyy-MM-dd_HH-mm-ss`；从开始就追加 `-00`，以后 `-01`、`-02`，不为补段号改名已发布文件；重名再加 `_2`。复用 `RecordingOutputTransaction` 的安全原则，扩展前缀/扩展名参数须新增测试，多轨目录发布也须独立覆盖，不能把既有 MP4 单文件测试当成已覆盖。

### 5.4 最小暂存集合、一次音频编码与空间预算

| 轨道 | chunk 格式 | 理由 |
|---|---|---|
| 音频单轨 | 仅 `mixed` PCM CAF，48 kHz / 默认立体声 / 16-bit | 不同时保存两份来源 PCM，避免三份暂存 |
| 音频多轨 / 视频音频 | 仅 `system`（立体声）与 `microphone`（默认单声道）PCM CAF | 不保存 mixed；麦克风立体声配置须按实际声道另算，不假定所有设备天生单声道 |
| 视频图像 | 每个 chunk 用 AVAssetWriter 首次编码为 H.264/HEVC MP4 | 每帧只编码一次，后续读取压缩样本直通，不重复编码 |

- **基线路径**：段内已提交 PCM chunk 按样本顺序解读，拼接处不重新开编码器；每个输出轨仅一个连续 AAC 编码上下文。CAF 用 `AVAudioFile`/CoreAudio 处理，不假定 AVAssetWriter 支持 CAF。
- **减少停止等待**：后台可从已提交 chunk 提前增量编码当前段，保持同一个编码上下文到段尾；不必等 59 分钟才开始。该 partial 不是恢复源，崩溃后可从仍保留的 PCM 重做。先用同一套路径验证，若增量模式不能保留 trim 元数据则不得启用。
- **停止后能听，不必等待最终文件**：停止接收并提交尾部检查点后，会话立即进入列表，允许从已关闭的 PCM/视频 chunk 做应用内草稿预览；来源同步混合，仍按正常段显示，不暴露分片。与“最终文件已保存”明确区分，未发布产物不允许用 partial 冒充分享文件。预览按需流式读，有引用的材料须在切到已发布文件/释放引用后再回收。
- **段内连续不等于跨段 AAC 天然无缝**：每个可见段仍有自己的 priming/padding，必须保存并验证有效样本范围。应用连续播放/导出按有效范围处理；不承诺任意第三方播放器逐文件连播都无间隙。
- **音频重处理边界**：未改内容的整段复制不重编码；需要混音、增益、裁剪或补齐时只编码音频。用户后续导出可对已发布 AAC 再编码，因此不是“整个产品生命周期音频只编码一次”；需要无损中间输出可另评估，不暗示 AAC 导出无损。
- **暂存按需写**：关闭/失联来源记区间，封装时流式生成静音，不为整段静音占满 PCM。默认预算仍按全时启用估算，不靠静音节省来保证安全。
- **空间公式**：`PCM = 48000 × 通道数 × 2 bytes × 秒数`。以下为十进制 GB，非 GiB，未含容器开销：

  | 配置 | 每小时 PCM | 每 59 分钟 PCM |
  |---|---:|---:|
  | 单轨混音立体声 | 0.6912 GB | 0.67968 GB |
  | 分轨：系统立体声 + 麦克风单声道 | 1.0368 GB | 1.01952 GB |
  | 旧稿三份 PCM（不采用） | 1.728 GB | 1.6992 GB |

- 视频 8 Mbps **目标码率估算**约 3.6 GB/小时；VBR 不可当成绝对上限。视频 Seal 时还会暂时共存一份完整 MP4，至少计入一次视频读和一次写，不能称“只封装、零 IO”。
- **动态预检**：按选中配置计算一段 PCM/视频暂存 + 一份发布 partial + 新段检查点 + 收尾预留。开始前校验该峰值；启用会增加轨道/声道的来源前重算预算，不够则保留旧路由并说明原因。运行时按实际文件增长、封装 backlog、卷可用空间更新，无法满足下一检查点及收尾预留时提前停止。检查目标卷与应用恢复目录所在卷，避免只检查其中一个。
- 不再写死“音频 3 GB / 视频 8 GB”或只按 5 分钟暂存估算。错误提示显示当前配置实际所需空间；开始阈值/继续阈值有滞回。
- ALAC、fragmented 写入仅可作为实测后的替换；压缩比、CPU 与掉电耐受不能先验保证，不用“约省 40%”替代预算。

### 5.5 轮转（chunk 与 segment）

**边界规则**（`RecordingSegmentPolicy`，纯类型）：

- `maximumSegmentDuration = 3540s`；检查点提交窗口目标 `maximumCheckpointAge = 300s`，不可关闭。为关闭 writer/持久化留出余量，通常在约 290 秒启动轮转；P0 校准余量，不能等到第 300 秒才开始异步收尾。
- 边界在样本/帧时间上判定：`globalTime < boundary` 进旧 writer，`>= boundary` 进新 writer；新 writer 的 PTS = `globalTime - boundary`。
- 每个 chunk 都在当前段末截短，不能出现 55–60 分钟的 chunk 跨过 59 分钟边界；多源共享边界，跨界 PCM buffer 精确拆分。
- 边界前预备下一个 writer（初始预算提前 5 秒），文件创建与编解码初始化不在采集回调；旧 writer 的 `markAsFinished`/`finishWriting` 在有序写入队列执行，不与 append 并发。
- 视频以原始像素输入新 chunk 的 writer，首帧须为可独立解码的同步样本；不能把非关键帧压缩包硬切进新文件。段边界向前对齐真实帧、偏差目标 ≤ 1 帧且总时长不超过 3540 秒，音频按同一实际边界落在 48 kHz 网格。静态屏幕无新帧时可用缓存像素首次编码边界帧；不算解码后重编码。帧前瞻/缓存及编码器交接由 P0 证明。
- 保留压缩样本的 PTS、DTS、duration 与格式描述；发生 B 帧重排时“append PTS 必须严格递增”不成立，必须按解码顺序提交并验证合法映射。禁止仅减 PTS 而丢 DTS。
- 新旧 writer 交接最多短暂共存两个视频编码上下文，不为每条音轨再开视频编码器。硬件不支持时须在 P0 修正交接，不运行到用户长录才失败。

**Seal**：

- 触发：段关闭（59 分钟）或会话停止。
- 方式：完成各轨剩余 PCM 编码与 AAC trim；视频 chunk 读取**压缩样本**，`outputSettings: nil` 且提供非空 `sourceFormatHint`，与独立来源音频复用封装。应用自己生成的全部 chunk 必须在 P0 证明格式可兼容直通，不能以“同分辨率/码率”代替该证明；若每 chunk 的编码上下文不能达标，应修正为原生持久编码上下文再做短单元封装，仍只首次编码、不削减恢复。拒绝不兼容拼接只适用于外部/旧格式资产，不能成为正常录制封装失败的借口。
- 任务并发默认 1，采集/检查点优先于 Seal，Seal 优先于用户导出/缩略图。增量编码不得饿死已结束段；backlog 按字节/预计处理时间有界，持续落后必须告警并在空间预算失守前安全停止。
- 单文件复用 `RecordingOutputTransaction`；多轨目录在同卷隐藏 staging 中写完全部轨和 manifest、校验后独占 rename，一次发布。目录不能用多个逐文件 publish 假装原子。
- **提交次序**：关闭检查点 → 提交恢复账本 → 编码/封装 → 校验可读、有效时长/轨数 → 持久化发布意图 → 原子发布 → 提交已发布记录 → 更新可重建索引 → 回收该段暂存。任一步失败保留最后可恢复集合。
- 正常录制不保留超长媒体总文件；未发布 PCM 只覆盖待完成段，有界 backlog，不随会话时长无限增长。耗时与停止等待均须实测，撤销原稿的“30–60 秒 / 10–20 秒”无证据估计。

### 5.6 元数据与会话索引

普通 `.m4a` 不会自动携带本产品的会话/段信息，需要显式写入自描述元数据；完整会话目录仍由可重建索引组织。

- **便携元数据**：多轨音频的 `manifest.json` 随目录走；单轨音频/MP4 在文件内写版本化 session/segment/track 元数据，使脱离应用索引仍可识别。视频多音轨映射不能只存在隐藏目录里。
- **应用内索引**：`~/Library/Application Support/SnapGlass/Recordings/index.json`，记录所有会话：
  ```json
  { "schemaVersion": 2,
    "sessions": [ { "id": "…", "kind": "screen", "layout": "embeddedSources",
      "initialAudioMode": "systemAndMicrophone", "sampleRate": 48000,
      "startedAt": "2026-11-11T15:30:00+08:00",
      "routeEvents": [ { "atSample": 14400000, "mode": "microphone", "deviceID": "…" } ],
      "segments": [ { "id": "…", "index": 0, "path": "…-00.mp4",
        "startSample": 0, "sampleCount": 169920000,
        "videoStart": { "value": 0, "timescale": 600 },
        "tracks": [ { "role": "system", "trackID": 2 }, { "role": "microphone", "trackID": 3 } ],
        "missingRanges": [], "bytes": 123, "state": "published" } ] } ] }
  ```
- 上述为 schema 示意，区间使用整数 `[startSample, sampleCount]`；`deviceID` 为本机 opaque ID，不含设备序列号，分享诊断前可去除。墙钟仅作显示标签，时区变化不影响顺序。
- **恢复账本是事实源，index 只是缓存**：每次检查点、route event、发布事务完成时提交该会话增量记录；不每 10 秒重写全部历史索引。活跃快照可 10 秒合并刷新，但不能替代检查点提交。
- **启动时对账**：先读轻量索引和未完成会话，再后台枚举已知录制目录；路径丢失 → `missing` + [定位]。新格式文件从嵌入描述/manifest 识别，绝不按文件名判断为旧录制。未完成发布意图按 segment ID 去重并补记，不重复导出。
- 无新格式描述的 v1.4 MP4 标“旧录制”，仍可播放、定位、做格式兼容性检查后进入导出计划；不能因没有新 metadata 永久剥夺裁剪/仅音频导出。无音轨的旧视频不伪造麦克风。
- 索引损坏从会话账本、便携元数据重建；不自动删除已发布文件。扫描仅限应用已知/用户选定目录，使用相对路径并校验越界、符号链接与 schema 版本，不全盘扫描。

### 5.7 崩溃恢复

- 目标卷隐藏目录 `.SnapGlassSessions/<uuid>/` 保存未发布媒体和恢复账本；应用支持目录保存可发现的会话登记。外置盘失联时提示重新连接，不误报为没有可恢复内容。
- 一个检查点只有在文件关闭/验证、必要持久化完成且账本标记 `committed` 后才可计为安全。音视频检查点是同一时间范围的集合，恢复到公共已提交尾端；不能一轨关闭成功就声称整段安全。
- 启动处理所有非终态（`recording`、`sealing`、`publishing`、`failedRecoverable`），不能只扫描 `recording`。校验孤儿已关闭 chunk，活动 partial 尽力抢救但不依赖其可读。
- 提示“发现未完成录制，可恢复约 X 分钟” + [恢复] / [稍后] / [移到废纸篓]；不向普通用户暴露“9 个 chunk”。丢弃需确认，未恢复材料不按缓存策略自动清理。
- 恢复按原段边界执行 Seal，仍不生成超长文件；命名加 `_recovered`，按 session/segment ID 幂等去重。已经发布成功但来不及更新索引的段只补登记，不重新编码、不生成重复文件。
- **保证范围**：目标是进程崩溃/强制退出、存储仍可读时恢复点窗口 ≤ 300 秒；若关闭/持久化拖延，HUD 显示安全点落后并进入故障收尾，不能维持虚假的 5 分钟保证。断电/介质损坏不能无条件承诺，同样需注入故障验证。
- PCM/视频原始分片在该段发布事务可靠提交前不得删除，即使增量 AAC 已追上。发布后回收仅限本事务拥有、可证明已被替代的临时材料，失败保留可重试。

### 5.8 录屏接入（三步迁移，不重写）

1. **抽取写入层**：writer 创建/输入/收尾抽成 `SegmentedWriterCoordinator`，只被新音频引擎使用，旧录屏路径不动。
2. **分离来源**：录屏音频进入共享对齐泵，按来源暂存；视频保留既有像素采集与编码配置，先用短会话验证 MP4 内多音轨。中间步骤只在开发开关后，不作为“已支持完整长录”的发布版本。
3. **接入分段**：视频与音频共用实际 `boundary`，协调器接管检查点/Seal/恢复。旧路径仅供开发回归对照，不允许作为用户运行中的静默 fallback（会绕开分段和恢复契约）。

### 5.9 拼接与导出

**计划（`RecordingExportPlanner`，纯逻辑）**

- 输入：索引中的会话 → 段列表 + 用户选择（段集合、每段 in/out、轨道方案）。
- 输出：`ExportPlan { requestedRanges, effectiveRanges, clips, trackMap, audioOperation, videoPassthrough, estimatedDuration, estimatedPeakBytes }`。
- 顺序：**强制按时间**，不支持打乱。
- 上限：`maximumExportDuration = 7170s (1:59:30)`；在裁剪吸附后按 `effectiveRanges` 重新校验。允许用户暂时选超限以裁剪修正，但禁用导出并显示超出量，执行前再次校验，不绕过恢复路径。
- 磁盘：按目标输出 + 工作 partial + 仍在进行录制的预留计算峰值，不能只乘最终大小 1.2；禁止输出覆盖任一源文件。
- **缺失区间补静音**：某轨在某段缺失（拔麦克风、设备切换、降级）时，导出按时间插入等长静音，绝不省略——省略会让后续内容整体前移、与视频失步。

**输出矩阵**

| 会话 | 输出选择 | 产物 |
|---|---|---|
| 音频·单轨 | 混音单轨 | `.m4a` |
| 音频·多轨 | 混音单轨（默认） | `.m4a` |
| 音频·多轨 | 保留分轨 | 目录：`system.m4a` + `mic.m4a`，按选段裁剪并从 0 对齐 |
| 视频 | 视频 + 保留来源音轨（默认） | 单个多音轨 `.mp4`，视频直通 |
| 视频 | 仅音频 | `.m4a`（会议转写常用） |
| 视频 | 仅音频·保留分轨 | 目录：来源 `.m4a` + `manifest.json`，不重复复制视频 |

**执行（`RecordingCompositionExporter`，后台 actor，可取消）**

- 视频：**仅直通裁剪**。起点取可独立解码同步样本，末端取满足解码依赖的有效边界；扫描实际 GOP/PTS/DTS，不承诺固定 ±1 秒。显示请求范围、实际范围及偏移，拖动时吸附，提交前再确认有变化的计划。
- 新录制 GOP 目标 ≤ 1 秒，须核实硬件编码器遵循；旧视频/导入视频按实际关键帧显示。**不提供精确重编码选项**；格式不兼容时说明不能直通拼接，保留分别导出/定位，不退回重编码。
- 音频与视频共同使用吸附后的有效区间。保留已有整轨且 trim/容器兼容时优先 AAC 直通；需要增益、混音、补静音或无法无缝直通的 AAC 接缝时，解码到正确有效 PCM 范围后仅重编码音频。视频导出始终保留来源隔离。
- `AVAssetReaderAudioMixOutput` 可用于已封装资产的混音；CAF 恢复走专门流式读取，不混用 API 假设。导出预览默认混合所有来源；单轨录音本来就不可再拆出原来源，UI 明示。
- 进度节流 4 Hz；取消停止任务、释放 writer 并只回收该任务拥有的临时文件，源文件/录制恢复材料不动；成功原子发布。录制进行中导出自动降优先级，进度显示“录制优先”而非假卡住。

### 5.10 与截图共存

- 删除 `RecordingCaptureAvailability.canBeginCapture(isRecordingBusy:)` 的录制侧拦截：录制中截图、滚动截图均可开始。
- 保留 `canBeginRecording(isCapturing:isScrollCaptureActive:)`：**截图进行中不开始录制**，避免两个 SCK 会话抢启动。
- 截图架、置顶面板、悬浮工具条保留 `sharingType = .none`，但不能据此断言所有系统版本的 SCK 一定排除；须验证 macOS 13 至当前版本。
- 录制 UI、截图遮罩/工具条与截图架使用统一窗口排除登记；新窗口出现或重建时更新 SCK filter，不仅在录制开始时收集一次 `excludedWindowIDs`，不重启视频/音频时间轴。`ShowcaseMode` 仅对明确允许展示的业务窗口例外，录制控制 UI 仍排除。
- 同时录屏与截图走现有 CaptureOrchestrator，实测并发启动/滚动抓取开销；能复用实时帧时复用，不能以“录制中暂不可截图”作为验收退路。
- 新增设置 `录制时隐藏截图架`（默认关）。开启后录制期间仅隐藏，不禁止截图；关闭时截图架可见且不入镜。
- **录制期间禁用截图音效**：否则提示音会被系统音频录进文件。
- 音频录制与视频录制仍然互斥（同一时刻只能一种录制），由 `CaptureViewModel` 统一判定。

### 5.11 权限

| 能力 | 触发 | 说明 |
|---|---|---|
| 屏幕录制 | 已有 `PermissionService` | 模式①③与录屏需要；引导文案写明"系统声音需要屏幕录制权限" |
| 麦克风 | 新增 `MicrophonePermission` | `AVCaptureDevice.authorizationStatus(for: .audio)` + `requestAccess`；主线程、应用激活 |
| 引导 | 复用 `window(id: "permission")` | 双卡片；麦克风拒绝 → `?Privacy_Microphone` |

- `Info.plist` 增加 `NSMicrophoneUsageDescription`；四语言用 `InfoPlist.strings`。
- 修正 `SnapGlass.entitlements` 注释里错误的 `com.apple.security.device.microphone`（应为 `device.audio-input`），本次不添加任何 key。
- 启动时只读复检，不主动索取新权限；签名/更新可能影响 TCC 的情况要实测，不能把本次版本的授权稳定性当成已知。缺权限时给明确提示，不静默降级。
- **升级迁移**：现有 `recording_systemAudio = true` → 新枚举 `systemAudio`；`false` → `none`（静音录屏）。旧用户升级后**不主动弹麦克风授权**，只有主动选择含麦克风的模式时才请求。

### 5.12 生命周期与录制中动态音源

```
session: idle → preparing/selectingSource → starting → recording → stopping → finalizing → finished/failedRecoverable
segment: collecting → closed → sealing → publishing → published/failedRecoverable
route:   active → preparingChange → committed/unchangedOnFailure
```

- Session 录制可与上一段 Seal 并行，不能用单一 `sealing` 状态阻断整个会话。停止后可立即开始下一会话；旧会话后台整理，受相同并发/空间预算约束，绝不共享可变 writer。退出确认同时覆盖活动录制与后台未完成保存。
- **切换步骤**：先准备新来源/格式/权限，旧来源继续；新来源准备好后在样本网格提交 route event，再释放不需要的来源。失败保持原选择并提示，不结束会话，不重置段数，不产出一组新文件。
- 单轨录音把 event 前后的启用来源自动混入同一个 mixed 时间轴；多轨录音/视频按 role 分离，新启用来源在当前段前半段补静音，旧来源之后补静音。
- 单轨切换/静音的增益变化使用短渐变（初始 5–10 ms，听测确定），混音/限幅状态不在 chunk 边界重置，避免人为“咔”声；不改变区间长度，不把不同来源串成先后播放。分轨不交叉混合，保留原位时间关系。
- 麦克风从未启用时不创建 tap、不读真实麦克风，关闭后释放采集；权限拒绝不影响已在录的另一来源。设备切换尽量先准备，系统不支持双输入并存时允许该来源重配间隙，按真实时标补静音并告知，不能承诺物理上不存在的零空档。
- 系统声音优先用 SCK `updateConfiguration` 热更新 `capturesAudio`，录屏只保留一个 stream；必须验证开关不会中断视频。若该平台路径不达标，在 P0 比较隔离音频 stream 的兼容路径及其开销，不允许把音源切换改回新会话。禁用来源不继续持有不必要的真实音频采集。
- 单路失效（拔麦克风、设备重配、权限撤回）不中断健康来源，缺失区间记原因；HUD 一次告警并提供重试/设备选择。全部来源暂时无声继续时钟并提示，静音不是暂停；纯音频长期无可用来源时给明确停止入口，不自行切成另一录制模式。
- 零有效录制时长/录屏零视频帧不发布空文件，但保留有恢复价值的音频材料并说明原因。用户主动静音的有效区间不等同于“零样本失败”。
- **锁屏 / 显示器休眠**：删除现有锁屏即停止分支，保留系统允许的音频采集；视频无新画面时明确显示画面暂不可用/冻结区间，不假装一直拿到新画面，也不绕过系统隐私限制。若系统终止 stream，进入可见的恢复/收尾路径。跨系统版本必须真机验收。
- **系统睡眠**：收到通知后停止接收并尽力提交当前检查点/保存；不能假定 OS 一定给足时间跑完 Seal。若被提前挂起，唤醒/重启后继续收尾或恢复，只有事务成功才提示“已保存”。继续录制需用户主动开始新会话。
- 退出应用：若有录制进行中，沿用现有 `RecordingQuitFlow` 确认并保存。

### 5.13 性能预算与完整体验的优先级

- **资源随当前段而非总时长增长**：内存为固定缓冲/缓冲池；文件句柄按活动来源与交接数有界；历史目录索引分页、懒读，不让 8 小时录制保留 8 小时内存对象。
- **减少不必要工作**：单轨只 mixed、多轨只 source；视频不多存伴随 M4A；不预先渲染整段波形；关闭来源释放设备；正常录屏复用 SCK；PCM 无额外压缩/解压循环。
- **时间预算**：采集回调 p99 < 2 ms、电平 UI ≤ 15 Hz、计时/VoiceOver ≤ 1 Hz、导出进度 ≤ 4 Hz；目标值须在指定硬件测试，不是已达到的性能声明。
- **稳态预算**：相同配置长录第 2 小时的 RSS 相比稳定后的第 10 分钟增长目标 < 32 MiB；录制无队列溢出，Seal 的处理吞吐持续高于新段生成速率。CPU/能耗、视频掉帧率、磁盘峰值、“停止→可预览”与“停止→最终保存”分别记录 p50/p95，P0 给出设备与阈值后冻结，不写无依据的总 CPU 百分比。
- **让后台让路，不让核心功能让路**：优先降速导出/缩略图，不关闭来源切换、截图或恢复；检查点不能仅因设置低 QoS 长期得不到执行。非必要分析懒执行，停止后提供真实“整理中”进度，完成态不提前出现。

## 6. UI 设计（UX 优先）

### 6.1 设计原则

1. **一眼知道在录什么、录了多久**：菜单栏与 HUD 永远同时呈现"模式 + 时长 + 电平"。
2. **默认路径零配置**：点菜单栏 → 开始录制。来源在设置里一次决定。
3. **不主动打断用户**：截图、切 Space、全屏、锁屏不触发产品主动停止；退出/系统睡眠按策略收尾，OS 撤销采集或存储故障明确告知，不假装无限可录。
4. **失败可见、可恢复**：任何失败都给出下一步动作（重试发布 / 打开目录 / 恢复会话），不使用纯错误码。
5. **不制造假承诺**：没有暂停就不放暂停按钮；不能混就不显示混合滑杆；不能精确裁剪就明说要吸附关键帧。
6. **动效克制**：只用于状态变化（开始、停止、段切换、完成），120–180 ms，`easeOut`；不做循环装饰动画。
7. **暗色优先，亮色同等对待**：全部使用语义色（`labelColor`、`controlAccentColor`、`.regularMaterial`），不写死十六进制。

## 8. 稳定性设计（长期项目视角）

### 8.1 不变量

| # | 不变量 | 保障方式 |
|---|---|---|
| I1 | 输出时间守恒：Σ 各段有效样本数 == 会话有效样本数 | 区分真实/重采样/静音/丢失区间；AAC 原始解码包数不是有效样本数 |
| I2 | 时序合法：音频样本网格单调，视频 PTS/DTS/解码顺序一致 | `AudioSampleClock` 与压缩样本映射；B 帧不能以 append PTS 单调作唯一判断 |
| I3 | 单写者：同一目标文件同时只有一个 writer | `SegmentedWriterCoordinator` 独占所有权 |
| I4 | 原子可见：完整产物通过校验后才发布 | 单文件安全发布；多轨目录同卷整体发布；账本可对账 |
| I5 | 权限不静默降级：不启用未授权来源，切换失败不破坏旧路由 | 权限/route 纯决策测试；旧版本不主动请求麦克风 |
| I6 | 采样队列无阻塞调用：无文件 IO、无锁等待、无 UI | 评审检查项 + `dispatchPrecondition` |
| I7 | 时间轴不因缺轨而位移 | 导出缺失区间补静音，planner 携带 `missingRanges` |
| I8 | 用户永远不需要处理 chunk | chunk 在隐藏目录，索引与 UI 只暴露 segment |
| I9 | 音源变更不改变 session ID、不触发段轮转或重启视频 | `RouteEvent` 在整数样本处提交，默认输入设备变化同样覆盖 |
| I10 | 自动录制产物/媒体工作文件不成为超长总文件 | segment ≤ 3540 秒；视频/PCM chunk 更短；主动导出 ≤ 7170 秒 |
| I11 | 不冗余落盘、不重编码视频 | mixed 与 source PCM 二选一；视频压缩样本载荷比对 |
| I12 | 未发布材料永不因索引滞后而误删 | durable checkpoint/发布意图先行；按 ID 幂等恢复；成功后才 GC |

### 8.2 故障预算

- 进程崩溃：恢复点窗口目标 ≤ 300 秒；只有已提交且存储可读的检查点纳入保证，检查点落后会触发告警/收尾（见 5.7）。
- 单路音频失效：会话继续，标 `degraded`，导出补静音。
- Seal 失败：保留 chunk，可重试；不发布半成品。
- 导出失败：源文件不动；临时文件清理；错误文案给出重试路径。
- 磁盘不足/外置盘离线：按真实暂存、发布 partial 与 backlog 更新预算；停止前保住最后检查点，断盘材料登记为待连接，不清理。
- 系统睡眠中途挂起：已提交检查点可恢复；唤醒后续办保存，未成功不显示“已保存”。

### 8.3 可观测性

- `Logger(category: "recording.audio")` / `"recording.segments"`。
- 关键计数：欠载/溢出、重采样修正量、时钟残差、丢失区间、视频丢帧、检查点年龄、轮转/Seal 耗时、backlog 字节、停止等待、设备事件。分位数/摘要写入 `diagnostics`，不每帧写日志。
- HUD 不展示原始技术指标，但必须呈现“未检测到声音 / 来源中断 / 保存滞后 / 空间不足”的可行动状态。诊断不写媒体内容；分享前可预览并去除本机路径、设备标识。

### 8.4 测试策略

| 层 | 覆盖 |
|---|---|
| 纯逻辑 | 480 帧/10 ms、时钟映射/±ppm、跨 chunk/segment 的 buffer 拆分、route event、整数边界、静音/缺失区间、有效范围吸附后上限、schema 编解码、发布/GC 幂等、权限决策 |
| 媒体集成 | 正弦/脉冲/扫频 + 真实 CAF/AAC/MP4；PCM 样本逐一核对；AAC 解码后的有效样本数与接缝质量；视频同步首帧/PTS/DTS/B 帧；内嵌轨数/角色；不重编码载荷比对；目录原子发布与元数据重建 |
| 故障注入 | 检查点关闭前后、AAC 编码中、发布前后、索引更新前后强杀进程；慢盘/断盘/写满；无声/设备重配/权限撤回；保证不删未发布材料、不重复产物 |
| 长时与真机 | 至少 2 小时 + 尾段与一轮 8 小时压力录制；系统/麦克风/双源、单/多轨、H.264/HEVC、内置/有线/蓝牙、锁屏/休眠、热切音源、录制中截图与滚动截图，记录 OS/硬件/CPU/RSS/IO/延迟 |

长时用例不能全部用缩短边界替代；短边界用于快速覆盖状态机，真实 59 分钟边界用于检查漂移、资源稳定性与封装追赶能力。AAC 是有损编码，不用“波形逐样本值相等”当作其通过标准。

### 8.5 迁移与回滚

- 三步迁移用于降低开发风险；公开版本须通过对应完整能力的门禁，不发布没有恢复的超长录制路径。
- 旧引擎只做开发回归对照；版本回滚不删除新媒体和账本，不让旧代码写坏较新 schema。遇未知 schema 只读保护、提示使用相应版本恢复。
- 设置有默认值，旧用户音源偏好按 5.11 迁移；**文件策略会变化**（59 分钟分段、视频来源内嵌分轨、锁屏不主动停止），必须提供一次简短说明，不能声称旧行为完全等价。

### P0 验证清单

环境至少覆盖 macOS 13、14、15 与当前 26 的可用真机/测试机；不可用项标明未测并阻止对应兼容承诺，不能把文档阅读当真机证据。

1. **SCK 音频路径**：纯录音 audio-only 与低帧率 2×2 对照；录屏复用已有 stream；系统静音/无帧仍维持正确时轴。只启动验证不够，还要测 CPU 与实际样本。
2. **动态路由**：系统→麦克风→双源→静音→恢复，含首次授权拒绝、切默认设备/蓝牙/拔插；session 不变，视频不重启，缺失区间可定位。
3. **双时钟与同步**：44.1/48 kHz 转换、±100/±300 ppm、回调抖动与长时水位；验证录音与 A/V 同步，不靠周期性硬丢样本过关。
4. **PCM→AAC 有效样本与接缝**：跨多个恢复 chunk 连续编码、可见段之间连续播放/再导出；核对 priming/remainder、有效样本数和脉冲位置。失败先修正确性，不能只看 asset duration。
5. **视频 chunk/segment 轮转与直通**：H.264/HEVC，同步首帧、静态画面、B 帧与 PTS/DTS，≤59 分钟上限；重封装前后压缩载荷一致，交接不因硬件编码器资源失败。
6. **MP4 内来源多音轨**：独立频率测试 system/mic，轨道 ID/角色/时长一致；中途开麦前区间静音；应用预览同步混合，记录 QuickTime/系统预览/剪辑软件的真实行为。
7. **崩溃事务矩阵**：检查点、编码、发布、索引、GC 各边界强杀；恢复公共尾端、损失窗口、孤儿/重复处理、多文件目录原子性、移动产物后的重建。
8. **截图共存与窗口排除**：开始/停止、长时录屏、热切来源、截图架新窗口、普通/滚动截图；无控制 UI 入镜、提示音或录制卡死。失败是阻塞项，不禁用截图规避。
9. **锁屏/休眠**：各系统的来源可用性、视频画面策略、睡眠中止 Seal 后唤醒恢复，区分已提交/正在保存；不假定系统睡前必能收尾。
10. **格式与元数据**：M4A 写入/有效样本 trim、CAF 读取、MP4 直通所需 format hint、嵌入自描述与目录 manifest 的往返；未知 schema/旧 MP4 导入。
11. **资源和空间**：持续 Seal/导出与采集并发，慢盘/外置盘断开/写满；测 RSS、回调 p99、吞吐、停止等待、检查点年龄与峰值空间，冻结 5.13 的硬件基线。
12. **权限/签名回归**：首次/拒绝/撤回、旧用户不开麦、不需要麦克风时不持有 tap；更新后 TCC 行为实测并明确引导，不扩大本轮签名工程。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 录屏引擎迁移 | 首帧启动/零帧失败处理回归 | 既有真实 writer 测试先行，三步开发迁移，不静默回退到无分段路径 |
| PCM 与封装峰值 | 新旧段、原材料与发布 partial 同时占空间 | 取消第三份冗余 PCM；动态峰值预算；事务提交后才回收 |
| 视频段边界 | 首帧不可解码、时间重排错误、硬件上下文不足 | P0 验证同步样本、PTS/DTS、短暂双 writer；不把预创建当证明 |
| 关键帧吸附裁剪 | 旧文件 GOP 很长，偏差大于用户预期 | 实测边界与偏移可见；无视频重编码兜底，不暗示任意帧可裁 |
| 外放回声（双源） | 麦克风重复拾取对方声音 | 录制前提示戴耳机；多轨导出可压低麦克风；单轨不可事后分离，voice processing 仅后续可选调研 |
| 接近 2 小时导出耗时 | 用户以为卡住 | 视频直通、必要时只处理音频；真实进度，估时以测量为据 |
| Seal 与录制抢 IO | 检查点落后、掉帧 | 统一预算/优先级、后台并发 1、有界 backlog，先让导出让路 |
| 更新后 TCC 变化 | 重新授权或来源不可用 | 只读复检、实测更新路径、明确引导；固定签名身份另行立项 |
| 截图与录制 SCK 并发 | 截图/录制抖动或 UI 入镜 | 热更新排除集合、复用可用帧、并发压力验证；不以禁用截图验收 |
| 索引与文件不一致 | 幽灵条目、重复恢复、材料误清理 | 事务账本、便携元数据、按 ID 对账；index 可重建 |
| 多音轨外部播放差异 | 外部播放器只播放一条来源 | 应用内默认混合试听，来源命名清楚，记录兼容性；不删除独立轨 |
| 动态设备切换 | 驱动重配间隙不可避免 | 同一时轴、原位静音、来源级告警与重试，不中止整个会话 |

## 11. 决定记录

| # | 决定 | 理由 |
|---|---|---|
| D1 | 音频多轨 = 同目录多文件 + 整数样本时间码；音频单轨自动混音 | 用户明确区分两种录音产物 |
| D2 | 视频按来源内嵌独立音轨，不默认另写 mixed/伴随音频 | 用户明确要求；避免冗余与来源丢失 |
| D3 | 分段 59 分钟，导出上限 1:59:30 | 两段拼满 1:58:00，留 1:30 裁剪余量 |
| D4 | 恢复暂存始终启用，目标提交窗口 ≤300 秒 | 正常分段不能取代崩溃兜底；为关闭/持久化预留余量 |
| D5 | 默认模式：音频录制 = 系统 + 麦克风；录屏 = 系统声音 | 会议是音频主场景；录屏保持既有默认，不擅自开麦 |
| D6 | 统一 48 kHz 时间网格，保留音质档与明确声道配置 | 单声道麦克风不为档位虚增为双声道；总码率按轨数展示 |
| D7 | 录制与截图彻底解耦 | 截图是 SnapGlass 的主能力，录制中不可用是明显缺陷 |
| D8 | 热键默认空，菜单栏优先 | 不替用户占用系统级快捷键；发现路径清晰 |
| D9 | 泵统一 host-time 与样本时间，渐进校正源时钟速率 | 定时器计数本身不能消除漂移；10 ms 为 480 帧 |
| D10 | 不引入新依赖、不改最低系统版本 | 长期可维护性优先于新 API 便利 |
| D11 | PCM 为恢复基线，段内每个输出轨连续 AAC 编码；允许后台增量 | 避免独立恢复分片反复产生 priming；跨段仍须 trim 验证 |
| D12 | 不自动合并会话，自动产物最长 59 分钟 | 用户明确目的：不出现超长录制文件；主动导出另受上限约束 |
| D13 | 音源/设备切换是同会话 RouteEvent，不轮转视频 | 用户明确否决结束重开；来源缺失不移动时间轴 |
| D14 | 恢复账本 + 便携自描述 + 可重建索引 | 安全事实不依赖 index 及时写入；单文件移动后仍可识别 |
| D15 | **导出缺失区间补静音，不省略** | 省略会让后续内容前移、与视频失步 |
| D16 | 视频全程直通，裁剪显示真实吸附范围，无精确重编码选项 | 用户明确不要视频重编码；音频处理单独披露 |
| D17 | **麦克风全链路原始信号，不做双链** | 多轨语义简单；AEC 留作 v2 可选 |
| D18 | 锁屏不主动停止；系统睡眠尽力收尾，提前挂起可恢复 | 不越过 OS 限制，不在保存完成前报告成功 |
| D19 | 最小必要轨集合、有界后台队列与事务提交后 GC | 性能优化不得削减动态切源、截图、多轨和恢复 |
| D20 | 功能、正确性、性能均为门禁；开发中按证据重估，P0 全矩阵在最终验收前补齐 | 不用旧 20 天数字或未测吞吐替代可交付证据 |

## 12. 留给实现者的自由

- 泵的唤醒粒度/缓冲目标可按实测调整，但采样速率、host-time 映射与恢复契约不能更改。
- 电平表的上限映射（线性或对数）由实现者按视觉测试决定。
- `AudioMixPolicy` 的软限幅曲线（tanh 近似或硬阈值）由实现者选择，只要不产生可闻失真。
- 缓冲池、索引分页与后台缓存结构按既有模式选择；schema 版本、便携元数据、原子发布次序不能省略。
- ALAC/fragmented 替换需补 P0 等价证据并修订本设计，不属于可静默替换的实现细节。
- 导出窗口的会话列表分组方式（按日期 / 按类型）由实现者决定。
